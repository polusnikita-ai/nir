# Имитационная модель многороботной системы (`multi-robot-sim`)

Программная реализация имитационной модели многороботной системы (МРС) для научно-исследовательской работы (НИР, 5-й семестр, НИУ «МЭИ», Институт ИВТИ, кафедра ВМСС, направление 09.03.01 «Информатика и вычислительная техника»).

## О проекте

Модель воспроизводит работу автономной группы мобильных роботов, выполняющих совместное обследование контрольных точек на 2D-полигоне со статическими круговыми препятствиями при ограниченном запасе энергии и отсутствии центрального диспетчера.

Ключевые компоненты модели:
- **Генератор сценариев и планировщик обхода препятствий** (`src/models.py`, `src/simulator.py`) — детерминированная генерация полигона `100 × 100 м`, статических препятствий, базы, контрольных точек и параметров роботов, а также построение безопасных маршрутов по графу видимости (`ObstaclePathPlanner`, алгоритм Флойда–Уоршелла, `0` коллизий).
- **Модель коммуникационной сети** (`src/network.py`) — связные статические топологии (`full`, `ring`, `line`) с учётом направленных доставок, объёма сериализованного трафика в байтах и опциональным журналом сообщений.
- **Децентрализованный аукционный протокол согласования** (`src/allocator.py`) — адаптация алгоритма CBAA с энергетическим фильтром допустимости, комбинированной ставкой $s_{ij}(\alpha)$ (безопасный путь + относительная энергонагрузка), децентрализованной фазой проверки флагов стабильности и переборным верификатором (`brute_force_best_round`).
- **Дискретно-временной движок исполнения** (`src/simulator.py`) — движение по полилиниям обхода препятствий, точный учёт энергетического баланса, автоматическая проверка инвариантов и экспорт подробных журналов наблюдателя (`--log-out`).
- **Визуализация и запись видео** (`src/visualizer.py`) — генерация 25-секундного видеоролика `demo/simulation_demo.mp4` (с поддержкой как `FFmpeg`, так и нативного кодера Windows Media Foundation H.264), наглядно показывающего обмен ставками в фазах аукциона, разрешение конфликтов, обход препятствий и расход заряда батарей.
- **Модуль парных экспериментов и масштабируемости** (`src/experiments.py`) — воспроизводимые серии из 360 основных запусков (3 топологии × 2 режима × 4 значения $\alpha$ × 15 сценариев) и 90 запусков масштабируемости ($n \in \{5, 10, 20\}$, $m \in \{20, 50, 100\}$) с расчётом среднего, медианы, стандартного отклонения и экспортом в CSV/JSON/PNG.

## Быстрый старт

### 1. Установка зависимостей

```bash
python -m venv .venv
.venv\Scripts\activate      # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

Для записи видео в MP4 используется `ffmpeg` (при наличии в `PATH`) либо встроенный кодер Windows Media Foundation (на Windows 10/11 дополнительные программы не требуются).

### 2. Запуск модульных тестов

```bash
python -m unittest discover -s tests -v
```

### 3. Запуск симуляции

```bash
# Одиночный прогон с выводом метрик и сохранением журнала наблюдателя
python main.py --mode single --robots 6 --tasks 20 --topology ring --alpha 0.5 --seed 42 --log-out results/demo_run_log.json

# Генерация 25-секундного демонстрационного видео (demo/simulation_demo.mp4)
python main.py --mode demo --duration 25 --video-out demo/simulation_demo.mp4

# Проведение серии из 360 парных экспериментов и 90 запусков масштабируемости
python main.py --mode experiments --seeds 15

# Полный цикл (видео + все эксперименты + графики)
python main.py --mode all --seeds 15
```

## Основные результаты экспериментов (360 + 90 запусков)

- **Нарушений ограничений и коллизий с препятствиями:** `0` во всех 450 запусках (резерв энергии ≥ 10 усл. ед., точный баланс расхода энергии, бесконфликтные назначения).
- **Инвариантность консенсуса по топологиям:** при фиксированном сценарии и $\alpha$ топологии `full`, `ring` и `line` дают идентичное покрытие (`88,22%` при $\alpha = 0{,}5$, неоднородная группа), но отличаются коммуникационными затратами (`1036,0` сообщений / `34,5` шагов для полного графа, `1243,2` / `103,6` для кольца и `1726,7` / `172,7` для линии).
- **Влияние энергетического веса $\alpha$:** в неоднородной группе наилучшее среднее покрытие достигнуто при умеренном учёте энергии $\alpha = 0{,}75$ (`91,11%` против `90,00%` при $\alpha = 1{,}00$; ΔK = `+1,11%`) со снижением удельных энергозатрат на одну точку с `28,63` до `28,34` усл. ед.
- **Масштабируемость:** миссия из `20` роботов и `100` точек рассчитывается в среднем за `~605 мс` при `0` нарушений инвариантов.

## Совместимость со смежными задачами НИР (открытые интерфейсы)

Ядро имитационной модели (`Задача 1А: Разработка имитационной модели многороботной системы`) спроектировано с открытыми программными контрактами (`src/interfaces.py`, `src/allocators.py`), позволяющими подключать алгоритмы и сервисы коллег без изменения движка симуляции:

| Смежная задача | Интерфейс расширения | Готовая реализация / адаптер |
| :--- | :--- | :--- |
| **Задача 1Б** (базовые методы MRTA) | `TaskAllocator` (`src/interfaces.py`) | `RoundRobinAllocator`, `GreedyNearestAllocator`, `OptimalAssignmentAllocator` (венгерский алгоритм) |
| **Задача 2** (децентрализованный аукцион) | `TaskAllocator` (`src/interfaces.py`) | `DecentralizedAuctionAllocator` (Energy-Aware CBAA по графу связи `full`/`ring`/`line`) |
| **Задача 3** (ставки с энергией и загрузкой) | `BidFunction` (`src/interfaces.py`) | `EnergyLoadBidFunction(alpha, beta_load)` — настраиваемые веса расстояния, энергии и загрузки |
| **Задача 4** (смарт-контракт / блокчейн) | `AssignmentLedger` (`src/interfaces.py`) | `InMemoryLedger` (SHA-256 цепочка раундов) и `HttpSmartContractLedger(endpoint_url)` для REST API |

### Пример сравнения всех 4 алгоритмов на единой сцене (`--mode compare`)

```bash
python main.py --mode compare --robots 6 --tasks 20 --seed 42
```

На тестовой сцене (6 роботов, 20 точек, `seed=42`, неоднородная группа) все алгоритмы отрабатывают с `0` нарушений ограничений:
- `round_robin` — покрытие **70,0%** (14/20), расход **54,31** ед./точку;
- `greedy` — покрытие **80,0%** (16/20), расход **46,35** ед./точку;
- `optimal` (венгерский алгоритм) — покрытие **85,0%** (17/20), расход **41,90** ед./точку;
- `cbaa` (Energy-Aware CBAA, `α = 0,5`) — покрытие **95,0%** (19/20), расход **37,91** ед./точку.
